# 12차 에셋 신청서 장법 개편

작성일: 2026-10-21  
수신: 이미지·애니메이션 에셋 제작 담당  
용도: 코드 담당에게 전달할 실제 게임용 PNG와 메타데이터 납품

## 1. 이번 납품의 목표

기준 문서는 [장법 4종 전투 로직과 시각 차별화 개편안](../../문서/기획/장법-4종-전투로직과-시각차별화-개편안.md)이다. **2번은 직선 장흔, 3번은 왕복하는 기환, 4번은 거대 월륜과 겹장**으로 구별한다. 이름·색상·크기만 바꾼 세트는 납품으로 인정하지 않는다.

1번 흑월장은 기존 에셋을 유지한다. 2·3번은 서로 다른 운용을 보이는 동급 장법이고 4번 투골장 극의는 화려하고 강한 후반 장법이다. 피해와 타이밍은 코드가 담당하며, 그림으로 임의 변경하지 않는다.

**주인공 몸체·얼굴·비율·머리·복장·기본 동작을 새로 그리지 않는다.** 전투 이펙트, 장법 아이콘, 4번 획득 소품과 연출 조각만 제작한다. 현재 조작은 좌클릭/J 기본 연계, E 강화 초식, 우클릭/F 월인, Q 월식이다. 이번 작업으로 월인·월식 이미지를 교체하지 않는다.

새 파일은 `main-game-r12/`에 납품한다. 기존 r10·r11 및 `본게임/assets/`의 실사용 파일은 덮어쓰지 않는다. 코드 담당이 검수 후 연결한다.

## 2. 먼저 확인할 기존 자료

- 본편 주인공: `본게임/assets/v9/`의 실제 몸체·팔·장력. 같은 캐릭터를 합성 검수에 사용한다.
- 기존 장법: `main-game-r10/manifest_palms.json`, `fx_palms_128.png`, `fx_palms_192.png`, 고리 앞뒤 PNG.
- 기존 장법 미리보기: `main-game-r10/preview/palms-*.gif`.
- 현재 전투 데이터: `본게임/src/combat/palm_styles.gd`.
- 기존 납품 형식: [11차 요청서](11차-납품-요청-본편-2구간.md).

쇄진장의 직선 모양과 회란장의 고리 질감은 참고하거나 원본을 편집해 사용해도 된다. 그러나 아래 슬롯의 크기·앵커·새 동작 규격을 충족해야 한다. 기존 시트를 확대하고 이름만 바꿔 납품하지 않는다.

## 3. 공통 제작 규격

| 항목 | 규격 |
|---|---|
| 게임 기준 | 800×450 논리 해상도, 주인공 보이는 키 약 48px |
| 원본 이미지 | 투명 RGBA PNG, 정수 픽셀, 안티에일리어싱·블러·사진 질감 금지 |
| 투명도 | 원본 알파 0 또는 255. 반투명은 코드의 레이어 opacity로 처리 |
| 외곽 | 기본 1px, 어두운 자주색 `#2a1420` |
| 소멸 | 흐린 알파 대신 픽셀 면적 축소·디더로 흩어짐 |
| 방향 | 방향성 이펙트는 +X, 왼쪽·공중 조준 회전은 코드 담당 |
| 크기 | 아래 표의 논리 크기, 기본 render_scale 1. 셀 바깥 2px 투명 여백 |
| 프레임 배열 | 클립별 독립 PNG, 8열, 좌→우·위→아래. 빈 마지막 셀은 완전 투명 |
| 피벗 | 클립 전체에서 고정. 프레임마다 잘라내기·중앙 재정렬 금지 |
| 글자 | 아이콘·연출 조각에 한글·한자·수치·버튼 글자를 구워 넣지 않음 |
| 타이밍 | 코드 이벤트 시간 우선. fps 일괄 변환으로 임팩트 시점을 변경하지 않음 |

팔레트는 장법마다 불투명 색 4개 이내를 기본으로 한다.

- 쇄진장: 외곽 `#2a1420`, 흑색 `#100b16`, 주홍 `#ee5048`, 밝은 심 `#ffe6df`.
- 회란장: 외곽 `#2a1420`, 흑색 `#100b16`, 적보라 `#c64c79`, 회보라 보조광 `#bca5d8`.
- 투골장 극의: 외곽 `#2a1420`, 흑색 `#100b16`, 진홍 `#ef355b`, 밝은 심 `#fff0df`.

장식 월륜만 실제 피해 범위보다 커질 수 있다. 반드시 `decorative: true`로 지정하고 캐릭터 뒤에 저불투명도로 그린다. 피해 표현용 장력은 표의 판정 외곽을 넘어 굵게 퍼뜨리지 않는다.

리드인은 모든 클립에 기계적으로 넣지 않는다. 준비 클립은 별도이며, **이벤트 순간 생성되는 타격 클립의 0번은 임팩트 프레임**이다. 마지막 프레임은 작은 잔광이어도 되지만 재생 종료 시 인스턴스를 제거한다.

파일은 `fx/<ID>.png`. 방향성 클립의 피벗 `(8,64)`는 전방 범위의 시작점이다. 길이는 피벗부터 +X 방향으로 잰다. 표의 폭은 세로 전체 두께다.

| `r12_fb_scar` | 128·(8,64) | 2장, 0.08초 후 마지막 홀드 가능 | 112×36px의 얇은 정지 균열. 3타 0.16초에 생성, 아직 피해 없음 |

E 경로는 실제 이동 거리에 맞춰 코드가 진행 방향으로 마스킹한다. 짧은 경로를 통째로 압축해서 선 두께를 바꾸지 않는다. 벽에서 끊긴 끝도 자연스러워야 한다.

장흔의 준비·점등·폭발은 같은 좌표에서 맞물려야 한다. 공중 3타는 손앞의 고정 장력 균열이므로 흙·돌 파편을 본체에 섞지 않는다. 바닥 먼지는 기존 효과를 별도 재사용한다.

## 6. 회란장 필수 클립

### 고리의 실제 크기

모든 고리는 **288셀·피벗 (144,144)**. 아래 반경은 띠의 중심선 반경이고, 안쪽·바깥쪽 경계는 `반경 ± 두께/2`다. 최대 외경은 E의 270px이므로 셀에 여유 있게 들어간다. 정면 원형을 유지하며 화면 원근 타원으로 납작하게 그리지 않는다.

각 행마다 `_back`, `_front` PNG를 따로 납품한다. 위쪽 반원은 back, 아래쪽 반원은 front로 나누고, 경계 픽셀은 한쪽에만 포함한다. 합성했을 때 정확히 하나의 고리여야 한다. 중심 내부는 투명하다.

| ID 접두어 | 공격 내 구간 | 중심선 반경 | 두께 | 장수 |
|---|---|---|---:|---:|
| `r12_rt_l1_out` | 1타 0.03~0.12초 | 24→68px | 22px | 12 |
| `r12_rt_l2_in` | 2타 0.03~0.12초 | 76→20px | 22px | 12 |
| `r12_rt_l3_out` | 3타 0.12~0.22초 | 24→100px | 26px | 13 |
| `r12_rt_l3_in` | 3타 0.30~0.44초 | 100→20px | 26px | 18 |
| `r12_rt_e_out` | E 0.20~0.34초 | 24→120px | 30px | 18 |
| `r12_rt_e_in` | E 0.42~0.58초 | 120→20px | 30px | 20 |

위 장수는 짧은 구간에서도 고리가 크게 뛰지 않도록 120Hz에 가까운 위치 샘플을 확보한 것이다. 한 방향 쌍의 위치 샘플 수는 93개, 앞뒤를 합친 실제 프레임 수는 186장이다. 각 반경 샘플을 재사용 가능한 원본 고리에서 자동 생성해도 된다. 임의로 프레임 수를 줄이지 않는다.

각 클립의 k번 반경은 `lerp(시작 반경, 끝 반경, k/(장수-1))`이며, manifest에 `sample_time`과 `radius` 배열을 기록한다. 코드가 구간의 정규화 시간으로 가장 가까운 샘플을 선택한다. 이것은 120fps 무한 루프가 아니라 구간 전용 위치 샘플이다. 충돌은 기획안대로 연속 검사하며 프레임 그림을 피해 발생 트리거로 사용하지 않는다.

### 동작과 구간 사이 표현

- 나가는 고리는 바깥 톱니, 돌아오는 고리는 안쪽 갈고리. 회전감도 반대다.
- 중심선 반경을 바꿀 때 선 두께까지 비례 확대하지 않는다. 띠 두께는 표의 값을 유지한다.
- 3타 0.22~0.30초, E 0.34~0.42초에는 out 마지막 장을 낮은 opacity로 유지한다. 이 홀드는 피해 구간이 아니다.
- 2타 시작 시 바깥 고리를 0~0.03초에 약하게 예고하고 0.03초부터 복귀한다. 별도 이미지 대신 in 첫 장을 재사용한다.
- 마지막 띠가 사라질 때 원 전체가 채워지는 폭발로 끝내지 않는다.
- 별도 `r12_rt_return_hit`: 64셀·(32,32), 4장·0.10초, 최대 36×36px. 적 표면에서 중심 쪽으로 접히는 작은 갈고리. 돌아오는 띠의 실제 명중 때만 재생한다.

고리 반경의 애니메이션과 앞뒤 렌더링은 현재 로더에 그대로 넣기만 하면 동작하는 형식이 아니다. 코드 담당은 sample 시간 선택과 고정 원점 재생을 연결해야 한다. 제작 담당은 판정을 추가하거나 코드를 수정하지 않는다.

`r12_bp_moon_great`의 프레임 시간은 `[0.05,0.05,0.05,0.05,0.05,0.05,0.05,0.05,0.07,0.07,0.0775,0.0775,0.0775,0.0775]`초다. 0~7번은 0~0.40초 월륜 전개, 8~9번은 0.40~0.54초 응축, 10~13번은 0.54~0.85초 접힘과 잔광이다. 새 피해 시점은 만들지 않는다.

시각 계층은 `배경 → 장식 월륜 → 캐릭터/적 → 실제 타격 앞면 → 적 예고/위험 표시 → HUD`를 기본으로 한다. 월륜 opacity 권장 0.25~0.35, 겹장 0.65~0.8이며 원본 PNG는 이진 알파다.

거대한 장인은 손가락 형태가 읽히는 무협 장력이어야 한다. 레이저포·총구·서양 마법진·거대 캐릭터 분신으로 바꾸지 않는다. 월륜은 속이 비거나 디더로 성기게 구성되어 몸 뒤를 완전히 검게 덮지 않는다.

4번이 가장 화려해야 하지만 화면 전체 흰색 플래시는 납품하지 않는다. 두 발경의 임팩트만 선명하고 잔광은 빠르게 얇아져야 한다.

## 8. UI와 획득 소품

### 장법 아이콘

`ui/r12_palm_icons.png`: 32셀, 3열 1행, 알파 0/255. 0번 쇄진장, 1번 회란장, 2번 투골장 극의. 각 아이콘 바깥 2px 투명 여백.

- 쇄진장: 직선 균열을 가르는 쐐기.
- 회란장: 바깥 톱니와 안쪽 갈고리가 대비되는 빈 고리.
- 투골장 극의: 월륜 앞에 겹쳐진 장인. 다른 두 아이콘보다 밝은 심의 비율을 높인다.

1번 흑월장 아이콘·메뉴 패널·선택 테두리는 재사용한다. 장법 이름·비용·설명은 코드 텍스트다. 기존 세이브 ID와 UI 정렬 순서는 바꾸지 않는다.

### 투골장 봉인함

## 9. manifest와 폴더 구조

```text
main-game-r12/
  README.md
  manifest_palms_r12.json
  fx/                         # 표의 클립별 PNG
  ui/                         # 아이콘과 펼친 비급
  props/                      # 봉인함과 봉인 해제
  preview/                    # 초식별 GIF
  contact/                    # 클립 ID·번호가 있는 검수용 콘택트 시트
  qa/                         # 실제 크기 합성·판정 비교·검수 결과
  sources/                    # 편집 가능한 원본, 자동 조립 스크립트가 있으면 포함
```

manifest 최상위는 `version: 12`, `effect_clips`, `ui_sprites`, `prop_sprites`로 나눈다. 기존 `effect_clips`의 sheet/cell/columns/first/count/pivot 필드를 유지하고 새 시간·샘플 필드는 별도로 추가한다. 새 필드 연결은 코드 담당의 작업이다.

```json
{
  "version": 12,
  "effect_clips": {
    "r12_fb_scar_burst": {
      "sheet": "fx/r12_fb_scar_burst.png",
      "cell": 128, "columns": 8, "first": 0, "count": 6,
      "pivot": [8, 64], "orientation": "hit_direction",
      "loop": false, "render_scale": 1,
      "duration": 0.20, "event_frame": 0,
      "origin_mode": "world_fixed", "layer": "attack_front",
      "decorative": false,
      "visual_bounds": {"shape": "forward_rect", "length": 112, "width": 36},
      "trigger": {"attack": "formation_breaker_light_3", "time": 0.34}
    }
  },
  "ui_sprites": {},
  "prop_sprites": {}
}
```

위 JSON은 1클립의 형식 예시이며, 실제 manifest에는 필수 슬롯 전체를 등록한다.

균등 프레임은 duration/count로 재생하고 월륜은 `frame_durations`를 사용한다. 고리에는 duration 대신 `sample_time`, `radius`, `band_width`를 기록한다. sample 시간은 해당 구간 시작을 0으로 잡으며 양 끝을 포함한다. 미리보기 24fps는 관람용일 뿐 게임 메타데이터를 24fps로 덮어쓰지 않는다.

반지름·공격 영역은 검수와 연결용 메타데이터이며 피해 판정을 이미지 로더가 자동 생성하라는 뜻이 아니다. 코드 전투 데이터가 판정의 기준이다.

## 10. 음향 담당 전달 항목

이미지 제작자의 필수 납품에는 WAV를 포함하지 않는다. 음향 제작을 함께 맡는 경우에만 아래 8개를 별도 납품한다. 무음 파일을 만들어 완료 표시하지 않는다.

- 쇄진장: `fb_pierce` 짧은 직선 파열, `fb_delayed_break` 낮은 지연 파열.
- 회란장: `rt_out` 상승하는 바람, `rt_return` 안으로 접히는 하강음.
- 투골장: `bp_palm` 묵직한 단타, `bp_gather` 수렴, `bp_first` 첫 발경, `bp_final` 낮고 넓은 최종 발경.

WAV PCM 48kHz·24bit·mono, 클리핑 없음, 불필요한 앞 무음 없음, 잔향 포함 1초 이내. 첫 발경과 최종 발경을 한 파일에 합치지 않는다. 게임 중 취소할 수 있어야 한다.

1. 장법 2·3·4번 각각 기본 3연계와 E를 보여주는 24fps GIF 총 6개. 공격 취소가 없는 정상 재생 기준.
2. 같은 기존 주인공을 사용한 800×450 합성 PNG: 1~4번 비교, 쇄진장 대시 이탈 뒤 장흔, 회란장 확장/복귀 비교, 투골장 E 최대 전개, 투골장 E와 적 예고 동시 표시, 무채색 4종 비교. 총 6장.
3. `qa/hitbox-overlay.png`: 주요 최대 프레임에 실제 범위 윤곽을 겹쳐 표시. 원본 PNG에 판정선을 넣지 않는다.

정상 동작 GIF 외에 취소·사망·피격 후 잔류 판정 검증은 코드 통합 뒤 수행한다. 합성 이미지만으로 게임에서 실제 작동한다고 보고하지 않는다.

## 12. 납품 승인 기준과 제작 순서

먼저 **2번 3타 장흔, 3번 E 왕복 고리, 4번 E 월륜+발경**을 실제 크기 합성으로 확인하고 나머지 클립에 동일한 기준을 적용한다. 중간 결과에서도 다른 캐릭터를 임시 주인공으로 넣지 않는다.

- 색을 제거해도 직선·왕복 고리·거대 겹장이 구별된다.
- 4번 E는 가장 크고 복잡하지만 적 예고와 캐릭터 위치가 보인다.
- 쇄진장 준비와 폭발의 위치가 같고, 경로 길이가 짧아져도 선 굵기는 유지된다.
- 회란장 앞뒤를 합치면 틈이나 겹친 심 없이 한 고리가 된다. 내부가 채워지지 않는다.
- 고리의 최대 반경과 띠 두께가 표와 맞고 셀에서 잘리지 않는다.
- 투골장 겹장 3개는 한 번의 타격, 3타·E 발경은 두 번의 타격으로 읽힌다.
- 장식과 실제 타격을 manifest에서 구분한다.
- 프레임·피벗·색상·시트 크기가 manifest와 일치한다.
- 기존 캐릭터와 실사용 에셋을 덮어쓰지 않는다.

최종 전달은 `main-game-r12/` 폴더와 같은 내용의 ZIP이다. PNG만 따로 전달하거나, 콘택트 시트를 실제 스프라이트 시트 대신 납품하지 않는다.
